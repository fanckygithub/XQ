# XScript 錯誤經驗與避坑指南

這份文件用於記錄開發過程中遇到的實際編譯錯誤、邏輯盲點以及 XQ 系統的隱藏限制，幫助後續開發建立長期的肌肉記憶，避免重複犯錯。

## 1. 變數命名地雷：禁止使用系統保留前綴
- **錯誤現象**：宣告變數 `var: tradeVol(0);` 時，系統報錯「"Trade" 不允許當成變數開頭，請更改變數名稱。」，並連帶導致後續使用該變數的判斷式出現「左右兩邊型態不同」的錯誤。
- **錯誤原因**：XQ 系統將 `Trade` 視為保留字首（例如系統內建的 `TradeDate`），因此不允許自訂變數以 `trade`、`Trade` 開頭。
- **正確寫法**：避開 `trade`，改用 `volToday`、`currentVol` 等變數名稱。
  ```pascal
  // ❌ 錯誤寫法
  var: tradeVol(0); 
  tradeVol = Volume;

  // ✅ 正確寫法
  var: volToday(0);
  volToday = Volume;
  ```
- **延伸實例 (慘痛教訓)**：在自動交易腳本中宣告外部參數 `input: TradeAmount(300000);` 同樣會直接引發編譯崩潰，連帶導致後面的數學運算如 `TradeAmount / 1000` 出現「左右兩邊型態不同」的詭異報錯。
- **正確對策**：針對資金與交易金額，一律改用 `InvestAmount`、`CapitalSize` 等非 `Trade` 開頭的字眼。
  ```pascal
  // ❌ 錯誤寫法
  input: TradeAmount(300000, "單筆投入金額");

  // ✅ 正確寫法
  input: InvestAmount(300000, "單筆投入金額");
  ```

## 2. 籌碼欄位正名：不可隨意簡寫
- **錯誤現象**：呼叫 `GetField("融資買進", "D")` 時，系統報錯「GetField 系列語法不支援此欄位名稱」。
- **錯誤原因**：XQ 的 GetField 對於欄位名稱的字串比對非常嚴格，不存在模糊對應或簡寫。
- **正確寫法**：必須給予完整的系統定義欄位名稱，例如 `融資買進張數`、`融資餘額` 等。
  ```pascal
  // ❌ 錯誤寫法
  value1 = GetField("融資買進", "D"); 

  // ✅ 正確寫法
  value1 = GetField("融資買進張數", "D");
  ```

## 3. 期貨未平倉量欄位名稱：必須使用系統英文保留字或特定寫法
- **錯誤現象**：使用 `GetSymbolField(targetSymbol, "未平倉量", "D")` 時，系統報錯「沒有未平倉量這個函數」。
- **錯誤原因**：XQ 對於總未平倉量，其內建的標準欄位為英文的 `OpenInterest`，中文對應名稱視版本可能為「未平倉口數」或不支援直呼「未平倉量」。
- **正確寫法**：一律使用系統標準保留欄位 `"OpenInterest"`。
  ```pascal
  // ❌ 錯誤寫法
  totalOI = GetSymbolField("FITXN*1.TF", "未平倉量", "D");

  // ✅ 正確寫法
  totalOI = GetSymbolField("FITXN*1.TF", "OpenInterest", "D");
  ```

## 4. 數學指數函數：禁止使用 Exp 
- **錯誤現象**：在計算數學 $e^x$ 時，輸入 `Exp(數值)`，系統報錯「Exp 關鍵字為保留字，目前版本不支援 Exp 語法」。
- **錯誤原因**：XS 系統將 `Exp` 保留給了財務報表欄位（代表 Expense 費用，例如 `Operating Exp.`）。
- **正確寫法**：若要進行數學的指數運算，必須改用 `Power` 函數配合自然對數底數 $e$ 常數（2.7182818）。
  ```pascal
  // ❌ 錯誤寫法 (無法編譯)
  Value1 = Exp(slope * 252);

  // ✅ 正確寫法
  Value1 = Power(2.7182818, slope * 252);
  ```

## 5. 相關係數 (Correlation) 與 時間序列 的計算陷阱
- **錯誤現象**：在計算價格與時間的 $R^2$ 時，若宣告 `var: timeIdx(0); timeIdx = CurrentBar;` 並使用 `Correlation(Close, timeIdx, 90)`，結果可能永遠為 1 或發生失真。
- **錯誤原因**：XQ 內建的 `Correlation` 等統計函數，在處理「單向遞增的自訂虛擬序列 (如 CurrentBar)」時，極易出現防呆或陣列歷史長度的內部對齊問題。
- **正確寫法**：計算迴歸 $R^2$ 時，捨棄 `Correlation`，改用純數學公式透過 `LinearRegSlope` 與 `StandardDev` 反推：
  ```pascal
  stdY = StandardDev(logC, length, 1); 
  varY = stdY * stdY;
  // R2 = (斜率^2 * (N^2-1)) / (12 * Y的母體變異數)
  if varY > 0 then 
      rSquared = (slopeRaw * slopeRaw * (length * length - 1) / 12) / varY
  else 
      rSquared = 0;
  ```

## 6. 系統保留字變數宣告衝突：禁止使用 condition 與 value 系列
- **錯誤現象**：宣告變數 `var: condition1(false), value1(0);` 時，系統報錯「"condition1" / "value1" 為系統保留文字，請更改變數名稱。」
- **錯誤原因**：XScript 系統已經內建了 `condition1` ~ `condition99` 以及 `value1` ~ `value99` 作為系統保留變數。雖然在某些腳本中可以直接使用不需宣告，但這違反了「所有變數必須在 var: 區塊中明確宣告並給予初始值」以及「要求語意化與駝峰式命名」的嚴謹開發準則。若強制在 `var:` 中宣告這些保留字，則會觸發編譯錯誤。
- **正確寫法**：徹底放棄使用系統保留字，改用具有明確語意且符合 CamelCase 規則的自訂變數。
  ```pascal
  // ❌ 錯誤寫法 (無法編譯)
  var: condition1(false), value1(0);
  condition1 = Close > Average(Close, 20);

  // ✅ 正確寫法
  var: isPriceUp(false), prevCrossIdx(0);
  isPriceUp = Close > Average(Close, 20);
  ```

## 7. 變數命名地雷：絕對禁止以 Buy 或 Sell 作為變數開頭
- **錯誤現象**：宣告變數 `var: buySignal(false), sellSignal(false);` 時，系統報錯「"Buy" 不允許當成變數開頭」、「"Sell" 不允許當成變數開頭」，並提示「開頭為保留字，目前版本不支援該語法」。
- **錯誤原因**：XScript 系統將 `Buy` 與 `Sell` 保留給自動交易系統的核心下單指令（如 `Buy("進場買點")`）。因此，只要自訂變數名稱是以 `buy`、`sell`（不分大小寫）開頭，都會被系統強制攔截並報錯。
- **正確寫法**：徹底避開 `buy` 與 `sell` 關鍵字，改用 `long`、`short`，或者 `goLong`、`goShort`，或是 `isBullSignal`、`isBearSignal` 來命名訊號變數。
  ```pascal
  // ❌ 錯誤寫法 (無法編譯)
  var: buySignal(false), sellSignal(false);
  buySignal = close > close[1];

  // ✅ 正確寫法
  var: longSignal(false), shortSignal(false);
  longSignal = close > close[1];
  ```

## 8. 選股腳本的隱形殺手：新上市股票與歷史期數越界 (Array Out of Bounds)
- **錯誤現象**：同一個腳本，在指標上畫得出訊號，但在選股腳本卻永遠選不出剛上市不久的股票（例如上市僅 160 天，但腳本使用了 `Highest(Close, 300)`）。
- **錯誤原因**：XQ 的「指標腳本」具備較高的圖表容錯性，遇到歷史資料不足時，會自動取現有 K 棒數（160根）來計算 `Highest`。但是，「選股腳本 (Scanner)」的底層引擎極度嚴格！當它試圖讀取過去 300 根資料卻發現只有 160 根時，會引發隱性的「陣列越界」或「資料不足」錯誤，並**直接強制略過該檔股票不輸出任何結果**，導致選股漏抓！
- **正確寫法**：針對會去抓取長期歷史區間的函數（如 `Highest`、`Lowest`），必須導入「自適應極值引擎（Expanding to Rolling Window）」，讓新股票累加極值，老股票才使用滾動區間。
  ```pascal
  var: maxHigh(0);
  // ✅ 正確寫法：自適應歷史長度
  if CurrentBar <= 300 then begin
      // 新股票：累積最大值 (Expanding Window)
      if CurrentBar == 1 then maxHigh = High else maxHigh = MaxList(maxHigh, High);
  end else begin
      // 老股票：標準滾動最大值 (Rolling Window)
      maxHigh = Highest(High, 300);
  end;
  ```

## 9. 指標與選股腳本對齊失真：UI 動態縮放陷阱與單一座標軸絕對映射
- **錯誤現象**：在圖表上使用獨立雙座標軸疊加不同量級的指標（例如 MACD 與 KDJ），肉眼看到有交叉訊號，但選股腳本卻選不出來。
- **錯誤原因**：XQ 畫面的「雙獨立座標軸」是基於「當下可見的 K 棒數量」進行動態縮放對齊。但選股腳本沒有畫面，只能使用固定的回溯期數（如 300 期）來計算基準線。兩者的縮放比例不一致，導致視覺交叉與數學交叉脫鉤。
- **正確對策 (絕對空間映射法)**：放棄 UI 的雙獨立座標軸。在程式碼內部，利用線性代數比例公式，強制將指標 B（如 KDJ）的振幅壓縮並搬移到指標 A（如 MACD）的數值空間中。兩者強制共用「單一座標軸」，讓數學等於視覺。
  ```pascal
  // 將 J 線絕對映射至 MACD 的極小數值空間
  if kdjA2 <> 0 then 
      jMapped = (valJ - kdjMin) / kdjA2 * macdA1 + macdMin 
  else 
      jMapped = 0;
  // 此後只需判斷 jMapped 是否穿越 MACD 的原生 0 軸即可
  ```

## 10. 選股腳本的時間差盲點：近 N 日訊號回溯記憶
- **錯誤現象**：指標畫面上明確標示了買點，但當天執行選股腳本時卻漏抓。
- **錯誤原因**：指標腳本是「歷史全盤標示」，買點可能發生在「昨天」或「前天」。但選股腳本預設只檢驗「今天（最後一根 K 棒）」是否滿足條件。如果今天沒有剛好交叉，自然選不出來。
- **正確對策**：利用 `BarsLast` 賦予選股腳本「短期記憶」，將條件放寬為「近 N 天內發生過發動訊號」。
  ```pascal
  // 取得距離上次共振訊號發生的 K 棒數
  var: signalBars(-1);
  signalBars = BarsLast(longSignal);

  // 只要今天、昨天、前天 (距離 0~2) 有發動過，就選出來
  if signalBars >= 0 and signalBars <= 2 then ret = 1;
  ```

## 11. 編譯器崩潰與幽靈報錯：絕對禁止使用雙等號 `==`
- **錯誤現象**：程式碼中不小心寫了 `if CurrentBar == 1`，結果系統報出一大串無關的錯誤，包含「找不到某變數」、「未宣告」、「缺少分號」等。
- **錯誤原因**：XScript 不支援雙等號 `==`。XQ 編譯器的底層容錯率較低，遇到無法解析的 `==` 符號時，會導致整個語法解析樹崩潰（Parser Crash），並向後吞噬周圍的程式碼，引發連鎖的幽靈報錯。
- **正確對策**：在 XScript 中，無論是變數賦值還是邏輯判斷，**永遠只能使用單一等號 `=`**。當遇到大範圍、不合邏輯的報錯時，第一時間先檢查是否多打了 `=`。

## 12. GetField 欄位頻率誤判：股本(億) 屬於日頻欄位，絕對不可改為 Q 或 M
- **錯誤現象（AI 誤判）**：將 `GetField("股本(億)", "D")` 中的頻率 `"D"` 認定為「錯誤」，並擅自改為 `"Q"`（季），理由是「股本屬於季報揭露欄位」。
- **錯誤原因**：這是對 XQ 資料庫架構的誤解。XQ 系統中，`股本(億)` 雖然在財報揭露時才更新，但其儲存格式被設計為**每日更新並存入日頻資料庫**，因此 GetField 對應的合法頻率是 `"D"`，而非 `"Q"` 或 `"M"`。
- **官方確認**：根據 XQ 官方說明文件（https://xshelp.xq.com.tw/XSHelp/?HelpName=股本(億)&group=TBASIC），`股本(億)` 欄位**僅支援日頻 `"D"`**。若在分鐘線腳本中使用，也必須顯式指定 `"D"` 才能正確讀取。
- **正確寫法**：
  ```pascal
  // ❌ 錯誤寫法（AI 誤將財報揭露週期等同於資料儲存頻率）
  mktCapBil = GetField("股本(億)", "Q");

  // ✅ 正確寫法（官方文件確認，日頻欄位，一律用 "D"）
  mktCapBil = GetField("股本(億)", "D");
  ```
- **延伸原則（肌肉記憶）**：**永遠不要用「財報更新週期」來推斷 GetField 的頻率參數**。XQ 欄位的合法頻率須以官方文件查閱為準，不可自行推斷。遇到不確定的欄位頻率，應先查閱官方 XSHelp 文件，再下筆。

## 13. 同一欄位在不同腳本類型中頻率參數不同：勿用指標寫法套用到選股
- **錯誤現象（AI 誤判）**：將指標腳本中 `GetField("發行張數(張)", "M")[1]` 與 `GetField("董監持股佔股本比例", "M")[1]` 的寫法，直接複製套用到選股腳本中，誤以為這兩個欄位在所有腳本類型下都是月頻（`"M"`）。
- **錯誤原因**：XQ 系統中，同一個欄位在不同執行環境（腳本類型）下，其可用頻率與正確的頻率參數**並不相同**。
  - **指標腳本（Indicator）**：因為可掛載在任意頻率的圖表（包含分鐘線、週線），必須顯式指定 `"M"` 並加 `[1]` 確保讀取已確認的月頻數據。
  - **選股腳本（Scanner）**：系統固定以日頻率執行，`發行張數(張)` 與 `董監持股佔股本比例` 直接以 `"D"` 讀取即可，**無需指定 `"M"` 也無需 `[1]` 偏移**。
- **正確寫法對照**：
  ```pascal
  // === 指標腳本寫法（掛在任意頻率圖表，需明確指定月頻） ===
  totalShares  = GetField("發行張數(張)", "M")[1];
  insiderRatio = GetField("董監持股佔股本比例", "M")[1];

  // === 選股腳本寫法（日頻執行環境，直接用 "D"） ===
  totalShares  = GetField("發行張數(張)", "D");
  insiderRatio = GetField("董監持股佔股本比例", "D");
  ```
- **肌肉記憶原則**：**從指標腳本改寫選股腳本時，必須逐一重新確認每個 GetField 的頻率參數**，不可直接複製貼上。腳本類型不同，執行環境不同，欄位的正確頻率可能跟著改變。

## 14. GetField 財報欄位不支援動態偏移 [i]：for 迴圈內的致命陷阱

- **錯誤現象**：在 `for idx = ... to ... begin` 迴圈內使用 `GetField("除息值")[idx]`，系統報錯「系統錯誤」或「陣列越界」，腳本無法執行。
- **錯誤原因**：`GetField()` 讀取的是財報事件欄位（如除息值、EPS等），**不是 K 棒技術序列**。XScript 中 `[N]` 偏移語法只對「K 棒技術序列（如 Close、Volume、Highest()）」有效。財報欄位不具備時間序列性質，因此 `GetField[idx]`（動態偏移）是非法語法，會導致系統崩潰。
- **正確對策（除息偵測）**：改用兩個都是技術序列的欄位做差值計算：
  - `GetField("收盤價", "D")[idx]`：未還原收盤（日頻技術序列，支援動態偏移）
  - `Close[idx]`：還原後收盤（K棒序列，支援動態偏移）
  - 兩者差值 > 0 → 代表有除息事件，差值即為除息值
  ```pascal
  // ❌ 錯誤寫法（GetField 不可動態偏移）
  for idx = 1 to 1260 begin
      exVal = GetField("除息值")[idx]; // 系統錯誤！
  end;

  // ✅ 正確寫法（改用技術序列差值偵測）
  for idx = 1 to 1260 begin
      exVal = GetField("收盤價", "D")[idx] - Close[idx]; // 兩者均為序列，合法
      if exVal > 0.01 then begin
          // ... 除息事件處理
      end;
  end;
  ```
- **正確對策（填息判斷）**：用 `Highest(Close, N)[idx-1]`（技術序列，支援動態偏移）取代內層迴圈，計算除息後N日內的最高收盤，效能大幅提升。
- **肌肉記憶**：**凡在 `for` 迴圈內需要讀取歷史資料，一律使用 K棒技術序列（`Close`、`Highest()`、`GetField("收盤價","D")` 等），絕對禁止用 `GetField` 財報欄位加 `[動態變數]` 偏移。**

## 15. 「填息天數」是選股欄位，不支援年度歷史偏移

- **錯誤現象（AI誤判）**：認為 `GetField("填息天數", "Y")[N]` 可以讀取近5年各年度的歷史填息天數，用來統計填息機率。
- **錯誤原因**：XQ 官方 API 確認 `填息天數`（英文名 `DaysForCashDividendAdjustment`）分類為「基本（FBASIC）選股欄位」，**僅能讀取最近一次除息的填息天數**，不支援年度歷史偏移 `[N]`。
- **正確替代方案**：若需統計近5年每次除息的填息情況，必須透過「K棒技術序列差值法」（見第14條）自行迴圈計算，無法直接用 `GetField("填息天數")` 歷史偏移達成。
- **可安全使用的場景**：`GetField("填息天數")` 只能用於「讀取最近一次除息結果」，搭配 `OutputField` 顯示，或做為「最近一次填息天數 <= N」的篩選條件。

## 16. 事件欄位（除權息日期、填息天數）完全支援歷史陣列 [N]

  ```pascal
  // ✅ 正確寫法（極速且不受還原權息設定影響）
  for i = 0 to 4 begin
      exDivDate = GetField("除權息日期")[i];

  end;
  ```
- **肌肉記憶**：若要統計過去 N 次的除權息、股利發放或特定事件，**首選絕對是直接在該事件欄位後方加上 `[i]`**。這不僅語法最簡潔，底層是直接查表，執行速度也是最快的。

## 17. 法人買賣超累加語法正名：必須使用 `Summation` 與精準欄位名稱
- **錯誤現象**：在計算法人近 N 日累積買賣超張數時，誤寫為 `SumValue(GetField("投信買賣超張數", "D"), 3)` 或 `SumValue(GetField("外資買賣超張數", "D"), 3)`，導致語法錯誤或無法正確編譯與選取。
- **錯誤原因**：
  1. 在 XScript 函數庫中，計算序列過去 N 期加總的標準函數名稱為 **`Summation(數值序列, 期數)`**。
  2. 投信與外資買賣超的精準欄位名稱為 `"投信買賣超"` 與 `"外資買賣超"`，不帶「張數」二字。
- **正確寫法**：
  ```pascal
  // ❌ 錯誤寫法
  itBuy3D = SumValue(GetField("投信買賣超張數", "D"), 3);
  fiBuy3D = SumValue(GetField("外資買賣超張數", "D"), 3);

  // ✅ 正確寫法
  itBuy3D = Summation(GetField("投信買賣超", "D"), 3);
  fiBuy3D = Summation(GetField("外資買賣超", "D"), 3);
  ```
- **肌肉記憶**：加總統計函數一律優先使用 `Summation`；牽涉到法人籌碼欄位時，必須牢記 `"投信買賣超"` 與 `"外資買賣超"` 的精確字串名稱。

## 18. 自動交易模組 SetPosition 不支援零股委託：底層架構限制與實戰解法
- **官方規範與限制**：
  根據 XQ 官方論壇確認，XScript 的「自動交易模組 (AutoTrade - Type C)」中，內建下單指令 `SetPosition(部位)` 的語法單位**被硬性規定為「整股張數」**。若在腳本中傳入小數點（如 `SetPosition(0.5)` 企圖下 500 股），系統引擎會**無條件捨去小數點**將其視為 `SetPosition(0)` 而不下單！
- **實戰解決方案（兩種標準 SOP）**：
  1. **零股專用流派（改走 Type B 警示腳本串接下單）**：
     若執意要全自動交易「盤中零股」，不可以掛在自動交易模組。必須改用「策略雷達 (警示腳本 Type B)」，利用 `ret = 1` 觸發訊號，並於軟體介面的【觸發設定 $\rightarrow$ 啟動下單】中，將委託市場切換為「盤中零股」進行固定金額或股數下單。
  2. **整股均等化流派（繼續在 Type C 自動交易模組，但加入張數捨去防呆）**：
     若維持使用 Type C 自動交易，必須利用 `IntPortion()` 將金額換算後的張數取整。若遇股價高過設定本金（如 10 萬買 250 元股票算出 0.4 張），系統自動捨去為 0 放棄該檔高價股進場，確保每一筆成功進場的部位都能控制在 10~15 萬元之間的整張委託。

## 19. 變數與參數命名嚴密避雷：「Buy」與「Sell」為系統保留字前綴 (致命陷阱與連鎖報錯)
- **錯誤現象與報錯訊息**：
  1. 當在腳本宣告 `var: buySig(false), buyCooldown(0);` 或 `var: sellSig(false), sellCooldown(0);` 時，XQ 編譯器會立即報錯：
     - `"Buy" 不允許當成變數開頭，請更改變數名稱。` / `「Buy」開頭為保留字，目前版本不支援「buyCooldown」語法。`
     - `"Sell" 不允許當成變數開頭，請更改變數名稱。` / `「Sell」開頭為保留字，目前版本不支援「sellCooldown」語法。`
  2. **連鎖型態報錯（極易讓人誤判為邏輯錯誤）**：由於上述變數宣告被編譯器直接拒絕並作廢，後續在程式碼中使用 `if buyCooldown > 0 then ...` 或 `buyCooldown = buyCooldown - 1` 或 `if buySig = true then ...` 時，編譯器無法識別該變數型態，進而產生大量令人困惑的連鎖錯誤：
     - `">" 左右兩邊的型態不同。`
     - `"-" 左右兩邊的型態不同。`
     - `"IF/Once/While/Repeat" 後面需要一個布林值或是布林值的判斷式。`
- **錯誤原因**：
  在 XScript 的底層語法解析中，`Buy` 與 `Sell` (不分大小寫) 是系統專屬的交易指令或保留字前綴（如 `Buy`, `BuyMarket`, `Sell`, `SellShort` 等）。任何自訂變數或參數名稱，**只要是以 `Buy` 或 `Sell` 開頭，都會被解析器判定為語法非法而直接作廢**！
- **正確寫法與修正方案**：
  變數與參數命名除絕對禁止使用 `daily`、`Trade`、底線 `_` 外，**絕對禁止使用 `Buy` 或 `Sell` 作為前綴**！請全面改用 `long`（多頭）、`short`（空頭）、`entry`（進場）、`exit`（出場）來取代：
  ```pascal
  // ❌ 致命錯誤寫法 (編譯直接失敗，並引發大串型態錯誤)
  var: buySig(false), buyCooldown(0);
  var: sellSig(false), sellCooldown(0);
  if buyCooldown > 0 then buyCooldown = buyCooldown - 1; // 報錯：> 與 - 左右型態不同

  // ✅ 正確避坑寫法 (將 Buy 改為 long/entry，Sell 改為 short/exit)
  var: longSig(false), longCooldown(0);
  var: shortSig(false), shortCooldown(0);
  if longCooldown > 0 then longCooldown = longCooldown - 1; // 完美編譯成功
  ```
- **肌肉記憶與自我迭代**：當看到 `">" 左右兩邊的型態不同` 或 `「Buy/Sell」開頭為保留字` 時，切勿去修改邏輯運算元！**第一時間立即檢查並更名所有以 `Buy` 或 `Sell` 開頭的變數**，更名後所有連鎖型態錯誤即可瞬間全數消失！

## 20. 副圖指標視覺化架構限制：副圖不支援 K 線/美國線，四價指標需降維為「雙線通道+極值點位」
- **官方限制與現象**：
  在 XQ 全球贏家的看盤介面中，「K線 (Candlestick)」與「美國線 (OHLC Bar)」等具備開高低收實體與影線的繪圖型態，**僅限定於主圖 (Main Chart) 使用**！
  當開發在副圖 (Sub-Chart，如 0~100 的 RSI/KD 空間) 運行的指標時，軟體介面的【設定指標 $\rightarrow$ 繪圖型態】**只提供「線條 (Line)」、「線段 (Line Segment)」、「柱狀圖 (Histogram)」與「點 (Dot/Point)」四種選項**，無法切換為 K 線！且因為 XQ 柱狀圖底層邏輯是「從 0 軸延伸至目標數值」，無法像通達信 `STICKLINE` 那樣在任意 $Y_1$ 與 $Y_2$ 之間懸空畫出實體蠟燭。
- **實戰解決方案（副圖降維視覺化標準 SOP）**：
  當欲將通達信/富途的「副圖蠟燭指標（如空心 RSI 蠟燭圖）」移植至 XQ 副圖時，必須進行**降維打擊映射**：
  1. **實體動能替代（雙線交叉法）**：將 RSI 的收盤快線 (`RSI_Close`) 設為粗亮色**「線條」**，開盤基線 (`RSI_Open`) 設為灰色虛線**「線條」**。當快線大於基線時即代表陽線實體，小於時即為陰線實體。
  2. **影線極值替代（包絡點位法）**：將 RSI 最高值 (`RSI_High`) 與最低值 (`RSI_Low`) 透過通道輸出，並在介面設定為**「點 (Dot)」**。高低極點會懸浮在快慢線上下方，直接形成視覺張力包絡線。
  3. **訊號導航替代（底部柱狀與極端點位）**：多空導航設定在副圖最下方 (0~10 數值)，繪圖型態設為**「柱狀圖」**；買進與賣出訊號則在 12 與 88 的固定高度輸出，設定為**「點 (Dot) 或 柱狀圖」**，讓轉折買賣點在副圖中直觀跳出！
- **肌肉記憶**：只要遇到「需要在副圖畫出 K 線或懸空蠟燭」的需求，立刻反應 XQ UI 限制，直接採用**「快慢線條 + 極值點位 + 底部柱狀圖」**的降維標準架構進行替代！

## 21. 跨平台移植致命陷阱：通達信 ZIG/TROUGHBARS/PEAKBARS 為「未來函數」，XScript 嚴禁使用並須降維為極值突破通道
- **錯誤現象與陷阱**：
  在通達信/富途等論壇或付費軟體中，常看到號稱「勝率 100%、買在絕對最低點、賣在絕對最高點」的主圖買賣點指標，其程式碼常包含 `ZIG(3, N)`、`TROUGHBARS(3, N, 1)`、`PEAKBARS(3, N, 1)` 或 `REFX` 等函數。若企圖將此類語法直接翻譯移植到 XScript，會發現無法達到圖表上的完美神蹟，甚至在盤中交易出現嚴重虧損。
- **錯誤原因（博士級揭露）**：
  `ZIG` (之字轉折線) 與 `TROUGHBARS`/`PEAKBARS` 在量化交易界被定義為最惡名昭彰的**「未來函數（Future-Leaking / Repainting Functions）」**！
  其底層邏輯是：必須等待股價從底部**已經向上反彈了 N% (如 6%, 22%, 51%) 之後**，系統才會「偷偷偷回溯到過去的 K 棒」，在當時的絕對最低點畫上買進訊號 `B`！
  在「歷史圖表與回測報告」中，因為未來的反彈已經發生，所以它看起來像個神，永遠買在絕對最低點；但在「盤中實戰」時，訊號會頻繁閃爍、漂移（今天破底出買點，明天再破底買點就消失），甚至嚴重滯後（反彈 72% 才跳出訊號，股價已到頂）！
- **實戰解決方案（無未來函數之標準改造 SOP）**：
  在專業量化交易與 XScript 開發中，**絕對禁止使用任何未來函數**！要實現「多週期波段轉折共振」，必須將 `ZIG`/`TROUGHBARS` 改造成**「真實無未來、不漂移的唐奇安極值通道與均線乖離突破」**：
  1. **波段低點確認（取代 TROUGHBARS）**：改為 `Close > Highest(High[1], length)`（突破過去 length 日之最高價）搭配 `Close > Average(Close, 20)`。
  2. **波段高點確認（取代 PEAKBARS）**：改為 `Close < Lowest(Low[1], length)`（跌破過去 length 日之最低價）或 `CrossUnder(Close, Average(Close, 20))`。
- **肌肉記憶**：一看到通達信或外來腳本中的 `ZIG`、`TROUGH`、`PEAK`、`REFX`，立刻在腦中拉響**「未來函數警報」**！絕不盲目翻譯，直接向用戶揭露其改寫歷史的陷阱，並採用 XScript 純淨無未來的**「極值突破與均線共振」**進行實戰改造！
